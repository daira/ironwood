# Verifier-fingerprint captures

Each capture is one run of the deployed Rust verifier, exported as the multi-scalar
multiplication (MSM) it would have evaluated together with the challenge schedule that produced
it. The Lean development proves that its own assembly reproduces that MSM.

## Layout

Families are organised by action count, then by what the capture is:

```
Fixtures/
├── Shared/              ScheduleMarker, TamperSweep — family-independent helpers
├── PostNu63.lean        cross-capture VK/URS equalities for the honest captures
├── PostNu63Random.lean  the same equalities extended to the random captures
├── SingleAction/
│   ├── Honest/          1 action, accepting run
│   └── Random/          1 action, random proof string
└── MultiAction/
    ├── Honest/          2 actions, accepting run
    └── Random/          2 actions, random proof string
```

**Honest** captures run the verifier on a real proof, so the MSM evaluates to the identity.
They are the non-vacuity witnesses, they feed the deployed capstone lane, and they carry the
per-slot sensitivity sweeps that name which proof field broke.

**Random** captures run it on a random proof string. The run completes but does not accept, so
the coefficient match is all these captures claim — they are match-only. They exist for the
slots whose honest values are recomputable from the key, publics, and challenges
(`fixedEvals`, `permutationCommonEvals`, `instanceEvals`): on a random proof string those carry
random values, so a sourcing error mismatches instead of hiding behind honest structure.

Honest modules never import match-only fixture data; the layout is meant to keep that visible.

## Which files are generated

`Fixture.lean` in every family is **generated by the halo2 exporter** and carries a
"Do not edit by hand" header. Its contents — captured points, the URS, the verifying key, the
challenge schedule, and the `fingerprint_matches` claim — are exporter output, as are the
`proof-bytes.hex` siblings in the match-only families. Editing either by hand breaks the
byte-for-byte CI gate and is overwritten by the next capture; changes belong upstream.

Everything else is hand-written: `FiatShamir.lean`, `Boundary.lean`, `Faithfulness.lean`,
`VkCertificate.lean`, `Negative.lean`, `Epsilon.lean`, and each family's `TrustBoundary.lean`
census.

`PROVENANCE.md` records the pinned release the captures regenerate from, the seeds, and how to
reproduce them.
